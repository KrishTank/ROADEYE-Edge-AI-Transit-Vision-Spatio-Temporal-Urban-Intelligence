1. Our Commitment to Privacy

At ROADEYE Technologies Private Limited ("ROADEYE", "we", "us", or "our"), privacy is not an afterthought or an administrative checkbox; it is the fundamental architectural foundation upon which our urban intelligence platform is engineered. We firmly believe that smart cities do not require pervasive mass surveillance. Modern municipal governance can achieve safer roadways, optimized traffic throughput, and rapid infrastructure repair without ever compromising the constitutional privacy rights of citizens navigating public spaces.

This Privacy Policy comprehensively explains how ROADEYE collects, processes, stores, protects, and governs information when municipal agencies, transport corporations, contractors, and individuals interact with our edge sensing nodes, mobile vehicle hardware, central web applications, APIs, and analytical tools. We operate in full compliance with the Digital Personal Data Protection Act, 2023 ("DPDP Act") of India, the Information Technology Act, 2000, and the Information Technology (Reasonable Security Practices and Procedures and Sensitive Personal Data or Information) Rules, 2011.

We act as a Data Fiduciary in respect of the account details and administrative credentials of registered platform users, and as a specialized Data Processor on behalf of contracting Municipal Corporations and State Transport Undertakings regarding public roadway spatial analytics.

2. Information We Collect

We collect only the minimum data strictly necessary to fulfill our civic mission of municipal infrastructure health assessment and transit fleet optimization. We classify collected data into four distinct categories:

A. Account Information

When an authorized municipal officer, contractor, or administrative user registers for access to the ROADEYE Command Center, we collect:

  • Official Identity Data: Full legal name, official governmental or institutional email address, department designation, municipal division, and administrative role (e.g., Command Center Operator, Field Maintenance Engineer, Municipal Commissioner).
  • Authentication Credentials: Passwords stored strictly as salted and hashed strings using industry-standard bcrypt or Argon2 cryptographic hashing; multi-factor authentication (MFA) device tokens; and cryptographic session tokens.
  • Organizational Contact Information: Department office address, official phone number, and agency billing details for contracted enterprise accounts.

B. Usage and Audit Log Data

To ensure absolute accountability, prevent unauthorized civic record alterations, and maintain forensic security trails, our systems automatically log:

  • Console Interaction Logs: Timestamps of user login sessions, pages viewed, filters applied on the Live GIS Map, work-order status updates, and reports exported.
  • Administrative Auditing: Identifiers of operators who dispatch field operations teams, acknowledge road hazard alerts, or alter algorithmic sensitivity thresholds.
  • API Consumption Metrics: Request counts, HTTP methods, latency figures, and client endpoints queried by authenticated API consumers.

C. Detection and Spatial Telemetry Data

Our edge compute units mounted on public transit buses generate high-frequency infrastructure telemetry:

  • Geospatial Coordinates: Real-time latitude, longitude, elevation, bearing, and speed of transit buses captured via multi-constellation GNSS (GPS/NavIC) receivers.
  • Inferred Surface Defects: Spatial coordinates and bounding box metadata for identified physical road anomalies, including pothole dimensions, asphalt fatigue cracking, longitudinal pavement fissures, waterlogging pooling areas, debris obstructions, and displaced manhole covers.
  • Inertial and Vibration Signatures: Three-axis accelerometer and gyroscope telemetry capturing vertical road impact shocks (G-force acceleration spikes) to measure roadway International Roughness Index (IRI).
  • Environmental Context: Ambient illuminance, approximate temperature, weather status indicators, and UTC timestamps.

D. Technical and Device Data

When accessing our web portals via desktop or mobile browsers, our servers record standard HTTP transmission parameters:

  • Network Identifiers: Internet Protocol (IP) address, approximate city-level geolocation deduced from IP, autonomous system numbers (ASN), and connection handshake telemetry.
  • Client Environment: Operating system type and kernel version, web browser family and build, screen viewport dimensions, CSS media query preferences (such as reduced motion), system language preferences, and user interface theme choices (light mode or dark mode stored in localStorage).
  • Performance Diagnostics: Page rendering latency, WebGL canvas performance benchmarks, Leaflet tile load times, and API response duration metrics used strictly for client-side software optimization.

We emphasize that technical parameters and network identifiers are logged strictly in connection with authenticated console security sessions. Unauthenticated visitors to our public portal (such as index.html or terms.html) generate only standard server access logs that are automatically rotated and purged after 90 days.

3. Legal Basis for Processing (DPDP Act 2023)

Under the Digital Personal Data Protection Act, 2023 (DPDP Act), processing of personal data is lawful only when anchored in valid statutory grounds recognized by Indian law. ROADEYE establishes its legal basis under Sections 4, 6, and 7 of the Act:

  • Consent (Section 6, DPDP Act): For registered user accounts, administrative personnel, and field operators, processing is anchored on voluntary, specific, informed, unconditional, and unambiguous consent accompanied by a clear affirmative action. Data Principals are furnished with an itemized notice detailing the exact categories of personal data requested, the operational purpose of processing, and instructions on how to withdraw consent at any time without punitive consequences.
  • Consent Managers: In accordance with Section 6(7) of the DPDP Act, ROADEYE will support interoperable, registered Consent Managers once operationalized by the Data Protection Board of India, enabling registered users to manage, review, and withdraw consent through accessible digital interfaces.
  • Certain Legitimate Uses (Section 7, DPDP Act):
    • Section 7(a) — Performance of State Functions: Assisting municipal corporations, smart city special purpose vehicles (SPVs), state road transport undertakings, and highway development authorities in fulfilling their statutory mandates. These functions encompass municipal road maintenance, hazard mitigation, bridge safety monitoring, pothole elimination, public transit scheduling, and disaster management during severe monsoon flooding.
    • Section 7(b) — Compliance with Law: Complying with any legal judgments, statutory orders, or regulatory directions issued by competent Indian courts, tribunals, or law enforcement agencies exercising lawful jurisdiction under the Code of Criminal Procedure, 1973 or Bharatiya Nagarik Suraksha Sanhita, 2023.
    • Section 7(d) — Medical and Public Emergencies: Responding to critical roadway emergencies, such as structural sinkholes, bridge distress, flash floods, or major multi-vehicle pileups where immediate telemetry dissemination is critical to protect human life and safety.
    • Section 7(f) — Public Health and Safety: Preventing infrastructure failures and hazardous roadway conditions that jeopardize vehicular safety and public transit commuters.
  • Contractual Necessity: Processing required to execute and fulfill institutional Service Level Agreements (SLAs) entered into with municipal corporations, urban local bodies (ULBs), and transport utilities.

ROADEYE acts strictly within the purpose limitation doctrine mandated by Section 8(1) of the DPDP Act. Data collected for civic infrastructure defect detection is never repurposed, cross-referenced with third-party consumer databases, or utilized for profiling, targeted commercial advertising, or credit scoring.

4. How We Use Your Information

ROADEYE utilizes the data collected strictly for the following operational and technological purposes:

  • Autonomous Infrastructure Defect Mapping: Aggregating detections from multiple passing transit vehicles to eliminate false positives and create definitive, high-confidence maps of road degradation for public works departments.
  • Dispatching Automated Work Orders: Generating structured work orders with spatial coordinates and severity indexes for municipal contractors and field engineers.
  • Real-Time Transit and Traffic Optimization: Computing corridor congestion metrics, average vehicular transit speeds, and route bottleneck predictions to assist city traffic management authorities.
  • Platform Security and Forensic Auditability: Monitoring system health, authenticating privileged administrators, and preserving tamper-evident records of civic governance decisions.
  • Edge AI Model Training and Calibration: Enhancing our YOLOv8 and computer vision models using non-personal, synthetic, and completely de-identified road surface imagery.

5. Data We Do NOT Collect

To provide complete transparency and eliminate any ambiguity regarding our technology, ROADEYE explicitly affirms that our edge systems and cloud infrastructure are designed with strict algorithmic boundaries. We do not, and will never, collect, process, or store the following categories of data:

  • No Facial Recognition Data: Our computer vision pipelines contain zero facial detection, facial landmark extraction, or biometric identification models. Any human figures appearing within camera views on public streets are either excluded from detection bounding boxes entirely or subjected to immediate on-device mathematical blurring before transient processing.
  • No Biometric Identifiers: We do not capture, record, or model retina patterns, fingerprints, voiceprints, gait dynamics, or unique physiological characteristics.
  • No Pedestrian Tracking or Personal Profiling: We do not track individuals across space and time. Our models count pedestrian cluster densities as anonymous spatial integers solely to assess pedestrian crossing safety near hazardous road zones.
  • No Sale of Data to Third Parties: We have never sold, rented, monetized, or leased any civic data, telemetry, or user information to third-party commercial data brokers, advertising agencies, or marketing syndicates.
  • No Advertising Trackers or Behavioral Ad Profiling: Our platform contains zero commercial advertising networks, zero retargeting pixels, and zero behavioral marketing tracking scripts.

7. Data Sharing and Disclosure

ROADEYE restricts data sharing to verified operational channels under formal contractual obligations. We share information only under the following clearly delineated circumstances:

  • Contracting Municipal and Transit Authorities: Aggregated telemetry, defect coordinates, road roughness ratings, and work orders are made available to the specific urban local body (e.g., BBMP, BMTC, State Road Transport Undertakings) that has contracted our sensing deployment.
  • Accredited Infrastructure Contractors: Authorized road repair contractors receive spatial work orders specifying defect coordinates and recommended material volumes to perform physical asphalt rehabilitation.
  • Cloud Infrastructure Providers (Data Processors): We utilize secure, sovereign cloud hosting providers located within India (e.g., AWS Asia-Pacific Mumbai/Hyderabad regions, National Informatics Centre compliant cloud infrastructure) that are contractually bound by rigorous Data Processing Agreements.
  • Statutory and Legal Mandates: We may disclose data if legally required to do so under a valid judicial warrant, summons, or statutory directive issued by an Indian court of competent jurisdiction or empowered statutory regulatory agency.

8. Data Localization (Indian Servers for Indian Users)

ROADEYE maintains an uncompromising commitment to Indian digital sovereignty and strict data localization. In compliance with the guidance issued under the DPDP Act 2023 and the directives of the Ministry of Electronics and Information Technology (MeitY):

  • 100% Domestic Data Residency: All production databases, spatial coordinate repositories, audit logs, user credentials, and machine learning telemetry are hosted exclusively on tier-4 enterprise data centers physically situated within the territory of India (specifically Mumbai and Hyderabad regions).
  • No Cross-Border Routing: Civic roadway telemetry generated by vehicles traversing Indian roads is processed, analyzed, and stored within domestic sovereign borders. No public infrastructure mapping data is routed to foreign servers for storage or analysis.

9. Your Rights under the DPDP Act 2023

As a Data Principal under the Digital Personal Data Protection Act, 2023, you are endowed with enforceable statutory rights regarding your personal data held by ROADEYE:

  • Right to Access Information (Section 11): You have the right to request a summary of the personal data we hold about you, the identities of all data fiduciaries or data processors with whom your data has been shared, and any other relevant operational details.
  • Right to Correction and Erasure (Section 12): You have the right to request the correction of inaccurate or misleading personal data, the completion of incomplete profile records, and the erasure of personal data that is no longer necessary for the purpose for which it was collected.
  • Right to Data Portability: You have the right to receive your personal data in a structured, commonly used, and machine-readable format (JSON/CSV) for transfer to another service provider.
  • Right of Grievance Redressal (Section 13): You have the right to readily accessible grievance redressal mechanisms regarding any act or omission of ROADEYE regarding your data protection rights.
  • Right to Nominate (Section 14): You have the right to nominate any other individual who, in the event of your death or incapacity, shall exercise your rights under the DPDP Act.

10. How to Exercise Your Rights

To exercise any of your statutory rights described in Section 9, please submit a formal written request to our Data Protection Officer at dpo@ROADEYE.ai or via our administrative Grievance Desk.

Your request must contain your full registered name, administrative role, municipal organization, and specific details regarding the right you wish to exercise. To protect institutional security, we will verify your identity before processing any data access, rectification, or deletion requests. We are committed to responding to and resolving all verified requests within thirty (30) days of receipt, free of any processing fee, in accordance with DPDP statutory timelines.

11. Cookies and Tracking Technologies

ROADEYE uses cookies and browser local storage strictly for essential, functional, and security purposes. We categorize our web storage mechanisms as follows:

  • Strictly Necessary Storage: Cryptographic session tokens and authentication cookies required to keep you securely signed in to the Command Center and verify role-based permissions across pages.
  • Functional Preferences (localStorage): Storing your interface preferences, specifically your choice between Light Mode and Dark Mode (stored as ROADEYE_theme), UI panel collapse states, and map layer visibility toggles.
  • Performance Diagnostics: Aggregated, anonymous client-side telemetry (e.g., page load latency, WebGL rendering frame rate) to diagnose application performance bottlenecks across various browser engines.

What We Do NOT Use: We do not use third-party marketing cookies, cross-site tracking pixels, Google Analytics tracking IDs, social media sharing beacons, or fingerprinting scripts. You can configure your browser to block or alert you about cookies; however, disabling strictly necessary cookies will render authenticated console features inaccessible.

12. Children's Privacy

The ROADEYE platform is an enterprise-grade municipal infrastructure management console strictly designed for authorized governmental and civic personnel. Our services are not directed to, intended for, or marketed to individuals under the age of eighteen (18) years. We do not knowingly solicit or collect personal data from minors. In accordance with Section 9 of the DPDP Act 2023, we do not undertake any tracking, behavioral monitoring, or targeted advertising directed at children. If we discover that personal data of a minor has been inadvertently collected, we will take immediate steps to delete such records from our persistent databases.

13. Technical and Organizational Security Measures

ROADEYE implements multi-layered, defense-in-depth technical and organizational security controls designed to safeguard civic telemetry and user data against unauthorized access, destruction, loss, alteration, or disclosure:

  • End-to-End Encryption in Transit: All HTTP communications across web consoles, mobile applications, and edge vehicle modems are enforced over Transport Layer Security (TLS 1.3) utilizing strong cipher suites with perfect forward secrecy.
  • Encryption at Rest: All database volumes, object stores, and rolling backups are encrypted at rest using AES-256 bit encryption with automated hardware security module (HSM) key rotation.
  • Edge Node Hardware Security: On-bus sensor compute modules feature tamper-resistant enclosures, encrypted eMMC flash storage, secure boot verification, and hardware-bound private keys for mutual TLS (mTLS) authentication.
  • Role-Based Access Control (RBAC): Strict principle of least privilege applied across all database records and API endpoints. Municipal users access only the territorial zones and functional modules authorized by their agency charter.
  • Continuous Vulnerability Management: Regular static code analysis, dynamic application security testing (DAST), automated dependency auditing, and third-party penetration testing conducted semi-annually.

14. International Data Transfers

ROADEYE does not transfer, export, or mirror personal data or Indian public infrastructure telemetry to any jurisdiction outside the Republic of India. In the event that future institutional collaborations necessitate cross-border data transfer, such transfers shall be strictly conditioned upon full compliance with Section 16 of the DPDP Act 2023, including ensuring that the recipient country is not blacklisted by the Central Government of India, and executing standard contractual clauses guaranteeing equivalent data protection safeguards.
